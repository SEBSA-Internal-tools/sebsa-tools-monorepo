# Local-auth manual test list

Temporary feature: remove this file with `apps/web/src/features/local-auth`.

No `.env` and no switch: the screens are always on, for people who are not signed in. In
development (`npm run dev:web`) the mock API answers every endpoint, as for the rest of the app; against
NestJS the same checks apply with real email.

Links look like `{APP_BASE_URL}/set-password#token=...`. In development:

- **Fixed QA links**, rebuilt on every page load:

  | Link                                      | State                                               |
  | ----------------------------------------- | --------------------------------------------------- |
  | `/set-password#token=demo-invite`         | Valid invite for `new.starter@sebsaworld.com`       |
  | `/set-password#token=demo-expired-invite` | Expired invite (resend works)                       |
  | `/set-password#token=demo-reset`          | Valid reset for `dheliya.kankanamge@sebsaworld.com` |
  | `/set-password#token=demo-expired-reset`  | Expired reset                                       |
  | `/set-password#token=demo-used`           | Already used                                        |

- **Dev outbox**: Add User, Resend invite, Forgot password and "Send me a new link" print the link to the
  browser console as `[dev outbox] … for <email>: <url>`. Open it in the same tab without reloading.
  Links and set passwords live in memory, so a reload forgets them; use Forgot password to get a fresh
  link for that account.

Against NestJS, get an expired, a used and an unknown token by waiting out the expiry, using a link
twice, and editing a character.
